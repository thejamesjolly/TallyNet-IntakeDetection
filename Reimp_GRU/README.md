# README for GRU Reimplementation

Reimplementation of code from the paper:
"Explainable CNN-GRU Model with Self-Attention for Suman
Activity Recognition Using Wearable Sensors through Data Augmentation" 
by Nadia Sultana, Sidratul Afrida, Bushra Akter, Tasnia Jahan, Afrin Ahmed, Mohammad Abu Yousuf, and Uddin, Md Zia [^SultanaGRU].


## Repository Contents

The model architecture for the PyTorch model is defined in `GRU_Classifier.py`.

Training is managed by `Train_GRU.py` and evaluation results are generated by `Eval_GRU.py`, with details on how to run them listed below.

Example models for each dataset are provided in the `Models/` directory.



## TO TRAIN MODELS

To train a model, use the following prompt in the command line.


`python Train_GRU.py [FolderName] [Cut] [Stride] [DATABASE_Flag] [FoldNumber] [TotalFolds] [OPTIONAL_ARGS]`

- Train_TallyNet.py
	* Python Script to train TallyNet model

- `FolderName`
	* Output folder location to store all files generated with the specific fold and model currently training

- `Cut`
	* Total duration of the window used as an input to the model
	* Units are in seconds

- `Stride`
	* Step which the dataset will slide the window forward through the motion data to generate the next example
	* Units are in Seconds

- `DATABASE_Flag` 
	* Flag used to select which dataset the model is working with
		- 1 = Dnd OREBA One-Handed
		- 2 = Dnd OREBA Two-Handed
		- 3 = Dnd Clemson
		- 4 = Dom OREBA One-Handed
		- 5 = Dom Clemson

- `FoldNumber`
	* Number of the fold used in k-fold validation (ranging from 1 to `TotalFolds`) used for training and testing split

- `TotalFolds`
	* Total number of folds used in k-fold validation



- `OPTIONAL ARGS`
    * Values can be modified, but have default values in training
    * `--arch [ModelArchFlag]`
    	- Model Architecture ID to modify the hidden layer structure of the model
            * 0 = Upper parameter count matching original paper
			* 1 = Lower parameter count matching original paper
			* 2 = Larger parameter count (larger hidden dimensions)
			* 3 = Recommended model, using default parameters 
				but lowering dropout rate for consistent learning 
			
    * `--fold-seg [FoldSegFlag]`
    	- Bool determining whether the k-fold validation is contiguous blocks or striped through all examples
    		* 0 = Block Segmentation
    		* 1 = Striped Segmentation (Default Value)
    
	* `--resamp [ResampFlag]`
    	- Resampling Rate in Hertz to which all datasets will be interpolated to match.
    	- Lower Sampling rate decreases memory and computation, but also model capabilities on harder datasets.
    	- Default Value: 16 Hz
	
	* `--gt-offset [float]`
		- Default Value = 1.0
		- Float between 0.0 and 1.0 for the percentage where to offset
		  labels within the input window 
		  (0.0 is the start of the window, 1.0 is the end of the window).



- Example
	* `python Train_GRU.py ExampleModel/models/fold1 10 0.3 2 1 5 --arch 3 > "ExampleModel/training_fold1.txt`











## TO EVALUATE MODELS

To evaluate a model, run the following command in the command line.


`python Eval_GRU.py [Folder_Name] [DatabaseFlag] [FoldNumber] [TotalFolds] [OPTIONAL_ARGS]`

- Eval_HeydReimp.py
	* Python Script used for evaluation

- `FolderName`
	* Name of the folder which contains the model .pb file
	* Should be the same as the training folder but with an additional `/models/foldN` appended to it, where N is the fold number
	* Does not end in a `/`

- `DATABASE_Flag`
	* Flag used to select which dataset the model is working with
		- 1 = Dnd OREBA One-Handed
		- 2 = Dnd OREBA Two-Handed
		- 3 = Dnd Clemson
		- 4 = Dom OREBA One-Handed
		- 5 = Dom Clemson

- `FoldNumber`
	* Number of the fold used in k-fold validation (ranging from 1 to `TotalFolds`) used for training and testing split

- `TotalFolds`
	* Total number of folds used in k-fold validation

- `OPTIONAL_ARGS`
	* `--stride [float]`
		- Default Value = 1.0 sec
		- Step which the dataset will slide the window forward through the motion data to generate the next example
		- Units are in Seconds
    * `--cut [float]`
		- Total duration of the window used as an input to the model
		- Units are in seconds
    * `--arch [int]`
		- Modifier for the internal hidden dimensions of the model.
		- Should match the value used in training
    * `--offset [int]`
		- Default Value: 1.0 (end of window)
		- Same as `--gt-offset` during training. 
	* `--resamp [int]`
		- Resampling Rate in Hertz to which all datasets will be interpolated to match.
		- Lower Sampling rate decreases memory and computation, but also model capabilities on harder datasets.
    * `--fold-seg [int]`
		- Default Value = 1
		- Bool determining whether the k-fold validation is contiguous blocks or striped through all examples
			* 0 = Block Segmentation
			* 1 = Striped Segmentation
    * `--save-preds [string]`
		- Filepath to save all model predictions to a `.csv` file
    * `--save-dets [string]`
		- Filepath to save all model detections to a `.csv` file
    * `--save-gts [string]`
		- Filepath to save all model ground truths used in eval to a `.csv` file
    * `--trigger [float]`
		- Value of the prediction to trigger a detection 
    * `--add-eval [int]`
		- Default Value = [1]
		- Evaluation to run on the generated predictions,
		  dictating how detections are paired to ground truth events
			* 1 = Point to Point Evaluation, 
				taken from Dong *et al.*[^DongHeurPaper]
			* 2 = Point to Window with Tolerance, 
				modified from Kyritsis *et al.*[^KyritsisMicroMotion]
	* `--tol [float]`
		* Default = 0.0
		- Tolerance used in Point to Window Evaluation, 
		  added to both sides of the window duration 
		  to match a possible detection within 





- Full Example
	* `python Eval_GRU.py ExampleModel/models/fold3_best.pt 4 3 5 --cut 10 --stride 0.2 --arch 3 --trigger 0.85 --add-eval 1 >> ResultsExample.txt`
